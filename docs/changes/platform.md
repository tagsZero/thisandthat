## PLAT-20261028-03 — 사용자 선택에 따른 공개 회원가입 기본값

- 날짜·종류·기능: 2026-10-28 / 기존 설정 기본값 수정 / PLAT-05.
- 실행 근거: 가입 방식 질문에 사용자가 **“누구나 가입하는 공개 회원가입”**으로 명시 응답했다. 이전 미응답 상태의 닫힘 기본값을 이번 선택으로 대체한다. PLAT-20261028-02의 최초 결함·보완·검수 결과는 당시 근거로 보존하고 소급 수정하지 않는다.
- 범위·소유권: 공통 인증 `app.py`의 `REGISTRATION_OPEN` 무설정 기본값을1로 변경하고 `.env.example`을 공개 가입 기준으로 맞췄다. `tests/test_registration.py`에 실제 무설정 가입/해시/로그인 검증을 추가하고 브라우저 fixture도 등록 환경변수와 dotenv 영향을 격리해 기본값 자체를 검사한다. root가 작은 설정 변경으로 직접 수행했다.
- 계약·문서: [PLAT-05](../ssot/04-platform.md#registration), 통합 SSOT·README·실행 매뉴얼·진행 현황·연결 대장을 최신 공개 정책으로 갱신했다. 등록 설정이 없으면 초대 코드 없이 누구나 가입한다. 명시 닫힘·초대 제한은 기존 운영 설정 호환으로 유지하며 공개 운영은 `REGISTRATION_OPEN=1`·초대 코드 미설정이다.
- 영향: 기본 폼 활성 상태/계정 생성 허용 변경 있음. 기존 입력/CSRF/중복/해시·가입 후 로그인 흐름 유지. 신규 계정의 TCI 공동 열람/수정·일정 수정/삭제 범위가 적용되며 K-HTP 소유권은 유지. 저장 payload·schema·API route·생성 파일·CSS/아이콘·의존성 변경 없음. 기존 계정/사용자 자료를 갱신하지 않는다.
- 실제 검증: `.venv`의 `python -m unittest discover -s tests` **212건·50.302초·실패0**(가입18건 포함). 무설정 폼 활성·초대 필드 없음·가입303·해시 저장·로그인을 새 메모리 SQLite에서 확인했다. 명시 제한·CSRF·중복·저장 실패·기존 기능 회귀도 포함했다.
- 브라우저: 격리 SQLite/Chromium156.0.8078.4의 **10개 검증군 통과**. 기본 공개1·명시 닫힘1·가입/오류/로그인/TCI 보고서/K-HTP 목록/모바일/초대 호환8개. JS 오류0·기존 보고서 동일·의도한 시험계정2개·QA서버 종료. 최신 결과는 로컬 `tmp/registration/result.json`이며 이전9검증군과 구별한다.
- 검증 한계: 작은 기본값 변경에 대한 이번 독립 재리뷰는 별도 실행하지 않았다. 이전 R1/재검수 기록은 이전 정책 범위다. 실제 PostgreSQL·운영 도메인·실서버 가입은 미확인이다.
- Git/운영: Git 명령·commit·push·배포·운영/로컬 `.env` 수정·실사용 계정 생성 미실행. 서버에 이전 제한 설정이 명시되어 있으면 사용자 운영 반영 시 매뉴얼대로 변경/재시작한다.
- rollback: app.py의 무설정 기본값과 예시·문서를 이전 정책으로 복구한다. 이미 생성된 계정 삭제는 별도 데이터 변경이다.
- 상태: 코드·문서 반영 및 자체 검증 완료. 실제 운영 반영·사용자 최종 판단은 별도다.
